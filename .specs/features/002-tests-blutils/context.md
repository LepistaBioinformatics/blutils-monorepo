# Context — Decisions for the test features

> Applies to `002-tests-blutils`, `003-tests-blutils-ui` and `004-tests-data-contract`.
> Status: **Draft — default decisions made by the agent, pending user confirmation.**
> Date: 2026-11-01

## D-01 — Policy for bugs found during mapping (TO BE CONFIRMED)

The mapping revealed behaviors that diverge from the as-built spec (`001-consensus-classification`)
or that are clearly defects (`BUG-Rxx`, `BUG-Uxx`, see each feature's design).

**Default adopted: characterization tests + disabled test of the desired behavior.**

- The main test **pins the current behavior** (passes today) and cites the bug ID in a comment.
- A second test describes the **desired behavior** and stays disabled:
  - Rust: `#[ignore = "BUG-Rxx: <summary>"]`
  - UI: `test.skip("BUG-Uxx: …")` (CRA 5's Jest 27 has no `test.failing`)
- Fixing a bug = removing the characterization test and enabling the desired one, in the same commit.

Alternatives discarded by default: (a) only tests of the correct behavior (suite is born red);
(b) only characterization (loses the record of the expected behavior).

## D-02 — Scope of production code refactoring (TO BE CONFIRMED)

The tasks were split into:

- **No production change** — the majority; only adds tests, dev-deps and test config.
- **`[REFACTOR]`** — minimal changes that exist only to enable testing:
  - UI: extract `groupedResults` (`Results/index.tsx:42-85`) and `chunk` (`Table.tsx:43-47`) into
    `src/functions/`; export `BeanSelectionRules.Rules`, `translateRank`, `markdownComponents`.
  - Rust: seam (trait) for the subprocesses without abstraction (`check_host_requirements`,
    `build_accessions_map`, `generate_fasta_file`, the `blastdbcmd` half of qiime).

Default: `[REFACTOR]` tasks stay **out of the first batch**; the same behaviors are covered
indirectly (via page/fake PATH) until the decision.

## D-03 — The as-built spec is not edited

Divergences between code and `001-consensus-classification/spec.md` (FR-IDENT-03, AC-03, AC-05) are
recorded as **pending discrepancies**; the spec only changes after the test confirms and the
user decides whether the code or the spec is correct.
